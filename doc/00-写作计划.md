# 《代码的联结》—— 写作计划

## 一、立意

这本书要讲的，不是"如何写代码"，而是**代码是如何彼此连接的**。

大多数编程书把代码拆成一个个孤立的知识点：变量、循环、函数、类……
读者学完之后，脑子里是一堆零件，却不知道这些零件是怎么咬合成一台运转的机器的。

本书反其道而行：**以"联结"为唯一主线**，从最小的连接单位讲起，
一层一层往外扩，直到一个完整的应用如何与它所在的整个系统连成一体。

> 核心隐喻：**代码不是一堆词语，而是一张不断放大的网。**
> 每一章都在回答同一个问题——"这一层，是靠什么连到下一层的？"

## 二、读者画像

- 主要读者：对编程好奇、但还没建立"整体感"的初学者；
  或者写过一些代码、却始终觉得"零散"的进阶新手。
- 阅读门槛：不要求读者会写代码，但要求愿意跟着思考。
- 写作语气：科普向。多用比喻、生活类比、图示；少用术语堆砌。
  每引入一个术语，先讲清"它解决了什么连接问题"。

## 三、贯穿全书的主角

为了让"从小到大"有连续性，全书围绕**同一个应用**展开——
一个朴素的「记账本」(暂名 *CoinJar*)。

- **卷一（单机篇）**：它是一个桌面应用，从一个函数长成一个完整的单机程序。
- **卷二（网络篇）**：它走上云端，从单机应用变成多人共享的 Web 应用，接入支付、对接外部世界。
- 每一章都在给这个应用"接上新的一层连接"，读者能亲眼看到它从最小的函数调用，一路长到跨越全球的网络连接。

## 四、结构总览

全书分三卷。**卷一讲"单机内的连接"，卷二讲"机器之间的连接"，卷三讲"人与 AI、AI 与世界的连接"。**
三卷讲的是同一种思想——"如何找到对方、如何可靠地传递、如何在更大尺度上协作"——在不断放大的尺度上的重演。

### 卷一　单机篇：一台机器内部的连接

| 部 | 主题 | 联结的尺度 |
|----|------|-----------|
| 序章 | 什么是"联结" | 建立直觉 |
| 第一部 | 函数与函数 | 最小的调用连接 |
| 第二部 | 模块与模块 | 功能的组织连接 |
| 第三部 | 文件与文件 | 物理与引用的连接 |
| 第四部 | 目录与目录 | 结构与边界的连接 |
| 第五部 | 代码与界面 | 逻辑与视觉的连接 |
| 第六部 | 应用与系统 | 程序与操作系统的连接 |

### 卷二　网络篇：跨越机器的连接

> 过渡：CoinJar 是个完整的单机应用了，但它困在一台机器里。
> 账同步不到手机，没法和家人共记一个账本。它要走出去——走上网络。

| 部 | 主题 | 联结的尺度 |
|----|------|-----------|
| 第七部 | 机器与机器 | 本机如何接入网络（物理与寻址） |
| 第八部 | 程序与程序 | 跨机器的"调用"：客户端与服务器 |
| 第九部 | 数据与云端 | 上传的数据如何存进服务器、又被读回 |
| 第十部 | 服务器与浏览器 | 服务器如何把网页送到浏览器 |
| 第十一部 | 网页与界面 | 网页如何成为新的"前厅" |
| 第十二部 | 身份与权限 | 用户账号如何注册、登录、被识别 |
| 第十三部 | 应用与外部世界 | 接入支付：和第三方服务的连接 |

### 卷三　智能篇：人与 AI、AI 与世界的连接

> 过渡：CoinJar 已经是一个连上了整个世界的云端应用。
> 但它仍然只会"按指令办事"——用户说一句"午饭18"，它记一笔。
> 它不理解人话，不会主动帮忙。AI 时代，连接迎来一次全新的放大：
> 让程序能听懂自然语言、能调用工具、能自主协作。

| 部 | 主题 | 联结的尺度 |
|----|------|-----------|
| 第十四部 | 人与模型 | 自然语言成为新的"调用方式"：从点按钮到说人话 |
| 第十五部 | 应用与模型 | 程序如何调用一个 AI 模型（模型 API、提示词） |
| 第十六部 | 模型与工具 | AI 如何反过来调用你的函数（工具调用 / function calling） |
| 第十七部 | 模型与知识 | 让 AI 连上你的私有数据（检索增强、向量与语义连接） |
| 第十八部 | 智能体与世界 | Agent：会规划、会自主调用多个工具完成任务的程序 |
| 第十九部 | AI 与 AI | 多个智能体如何协作（多智能体、协议、编排） |
| 终章 | 联结，是一切的钥匙 | 回望从一个函数，到人机协同的智能网络 |

> 卷三待定，框架先行，具体章节随写作推进细化。CoinJar 在卷三将长出一个"会聊天、会自动记账、会帮你分析消费"的 AI 助手。

### 三卷之间的"连接暗线"

全书不是三个独立主题，而是同一种"连接思想"的三次放大。每一卷的新概念，都能在前面找到"原型"：

- **系统调用**（第六部）→ **网络请求**（第八部）→ **模型 API 调用**（第十五部）：都是"向边界外的强大存在提要求"，边界从"系统"到"另一台机器"再到"一个 AI 大脑"。
- **路径**（第三、四部）→ **IP / 网址**（第七、八部）→ **语义检索 / 向量寻址**（第十七部）：都是"如何找到对方"，寻址从"精确地址"演进到"按含义匹配"。
- **接口/协议**（第二、七部）→ **API**（第八部）→ **提示词 / 工具描述**（第十五、十六部）：都是"靠共同约定让独立双方协作"，约定从"严格格式"演进到"自然语言描述"。
- **事件→调用**（第五部）→ **网页事件→网络请求**（第十一部）→ **人话→意图→工具调用**（第十四、十六部）：用户动作触发程序行为，触发方式从"点击"演进到"说一句话"。
- **回调**（第五部）→ **支付回调**（第十三部）→ **Agent 的自主循环**（第十八部）：从"你变了喊我"，到程序能自己决定下一步喊谁。
- **函数调用**（第一部）→ **路由接力 / 客户端服务器**（第七、八部）→ **多智能体编排**（第十九部）："一个喊另一个帮忙"，从函数之间，到机器之间，到 AI 之间。

## 五、每章的固定骨架

为了让读者有稳定的节奏感，每一章尽量遵循同一套结构：

1. **一个问题** —— 上一层留下的"断点"：这里为什么连不上去了？
2. **一个比喻** —— 用生活中的连接现象类比。
3. **拆解机制** —— 这一层的连接到底靠什么实现。
4. **回到 CoinJar** —— 在主角应用上动手接一次。
5. **断点预告** —— 这一层接好了，但又冒出新的断不上的地方，引出下一章。

## 六、写作进度约定

- 先定目录（`01-目录.md`），再逐章填内容（按 `章节号-标题.md` 命名）。
- 每完成一章，回到本计划勾选进度。
- 暂不追求代码语言统一，示例以"可读优先"，必要处标注语言。
