# 第六部　应用与系统 —— 程序接上世界

---

## 6.1　断点：保存文件、弹出窗口，应用自己做不到这些

上一章结尾，我们问出了几个釜底抽薪的问题。这一章，我们要回答它们。

让我们再逼问 CoinJar 一次。它现在有了漂亮的窗口、能记账、能显示。可你试着做两件最朴素的事：

1. **关掉 CoinJar，再重新打开。** ——你昨天记的账，全没了。
2. **仔细想想那个窗口。** ——它凭什么能出现在你的屏幕上？

第一件事暴露了：CoinJar 的账目，一直只存在于**运行时的内存**里。内存是"临时的"——程序一关，内存被收回，数据灰飞烟灭。要想"存住"，必须把数据写到**硬盘**上。可 CoinJar **自己没有能力**去驱动硬盘——它发不出让磁盘磁头转动、让数据落到盘片上的那种最底层的指令。

第二件事更根本：那个窗口能画在屏幕上，是因为有谁在**控制你的显示器**。CoinJar 同样没有能力直接去点亮显示器上的每一个像素。

> 一个扎心的事实：
> **CoinJar 这样的应用程序，其实什么"硬"事都干不了。**
> 它不能直接碰硬盘，不能直接碰显示器，不能直接碰键盘鼠标，不能直接碰网卡。
> 它就像一个**手无寸铁、却满脑子想法的"大脑"**——
> 想存账、想显示、想读取输入，可它**没有手脚**去直接触碰真实的硬件。

那么，前五章里那些"存起来""弹窗口""读输入"，到底是谁替它做的？

答案是一个我们一直依赖、却从未正眼看过的庞然大物——**操作系统**。这一章，就是要看清 CoinJar 和它脚下这片叫"系统"的大地之间，那最后一层、也是最大尺度的连接。

---

## 6.2　比喻：住进一栋公寓，水电网都是物业供给的

想象你租了一套公寓，住了进去。

你能用电灯、能用自来水、能上网、能用电梯。但请你想想：**这些是你自己造的吗？**

- 你打开水龙头就有水——可你没挖水井、没建自来水厂。水，是**物业/市政**通过管道送进来的。
- 你按开关就有电——可你没发电。电，是**电网**通过电线送进来的。
- 你能上网——可你没拉光缆到小区。网，是**运营商**接进来的。

你这个住户，**几乎什么基础设施都没造**。你只是住进了一栋**早已配好水电网的大楼**，然后通过**水龙头、开关、网口**这些标准接口，去"**取用**"楼里供给的资源。

你和大楼的关系是这样的：

- 你不能自己去碰主电缆、主水管（太危险，也会影响别的住户）；
- 你想要水，就**拧开水龙头**——这是大楼允许你"提要求"的标准方式；
- 大楼收到请求，从它统一管理的资源里，分一份给你。

把这套搬到代码世界，那栋"早已配好一切基础设施的大楼"，就是**操作系统**：

> **操作系统，是所有程序共同居住的那栋"大楼"。**
> 它早已驯服了硬盘、显示器、键盘、网卡这些"基础设施"，统一管着。
> 你的应用（CoinJar）只是住进来的**一个住户**。
> 它想存文件、想弹窗口，**不能自己去碰硬件**，只能像拧水龙头一样，
> 通过系统提供的**标准接口**，向系统"**提要求**"。

而那个"水龙头"——应用向系统提要求的标准方式——有个正式的名字，叫**系统调用**。

## 6.3　操作系统是什么：所有程序共同的"地基"

我们把"大楼"说得再准确一点。

**操作系统**（Operating System，常简称 OS）——你电脑上的 Windows、macOS，手机上的 Android、iOS，都是操作系统——是一个特殊的、最先启动、并且**一直在后台运行**的超级程序。它干两件大事：

**第一，它驯服硬件。**
硬盘、显示器、键盘、鼠标、网卡、内存……这些硬件，每一种的"脾气"都不同，直接操控它们极其繁琐、极其危险。操作系统把它们全部**接管**下来，藏在身后，对上层屏蔽掉所有可怕的细节。

**第二，它当大管家。**
你的电脑上同时跑着几十个程序：浏览器、音乐、聊天、还有 CoinJar……它们都想用 CPU、想用内存、想读硬盘。如果让它们自己抢，瞬间就乱套了。操作系统做那个**居中协调的大管家**：决定谁先用 CPU、给每个程序分多少内存、谁能读哪个文件。

于是操作系统就成了所有程序脚下那块**共同的地基**：

```
    ┌────────┐ ┌────────┐ ┌────────┐ ┌────────┐
    │ 浏览器  │ │ 音乐    │ │ 聊天    │ │CoinJar │   ← 住户：各个应用程序
    └────────┘ └────────┘ └────────┘ └────────┘
    ══════════════════════════════════════════════
                  操作系统  （大楼 / 地基）          ← 驯服硬件、协调资源
    ══════════════════════════════════════════════
    ┌────────┐ ┌────────┐ ┌────────┐ ┌────────┐
    │  CPU   │ │  内存   │ │  硬盘   │ │ 显示器  │   ← 硬件：基础设施
    └────────┘ └────────┘ └────────┘ └────────┘
```

请你注意这张图里的**分层**——它又是我们的老朋友了！

> 第五章，我们把"界面"和"逻辑"分了层。
> 这一章，**整台计算机**也是分层的：**应用层 → 操作系统层 → 硬件层**。
> 上层永远不直接碰最底层，而是**通过中间层提要求**。
>
> 这是"分层"思想的**终极版本**——它不再只是你程序内部的设计选择，
> 而是**整台计算机的根本架构**。从函数到整机，"分层 + 通过接口连接"是同一个道理，反复重演。

CoinJar 住在最上面那层。它和硬件之间，永远隔着操作系统这位大管家。它想干任何"硬"事，都得**隔着这位管家提要求**。怎么提？就靠下一节的"系统调用"。

## 6.4　系统调用：应用向系统"提要求"的标准方式

**系统调用**（system call），就是应用程序向操作系统"提要求"的那个标准动作——公寓比喻里的"拧开水龙头"。

它的样子，你其实**一点都不陌生**。当 CoinJar 想把账目存到硬盘，它代码里大概会这样写：

```
保存到文件("账目.txt", 账目数据)
```

看到没有？**它长得和一次普通的函数调用一模一样。** 这绝非偶然——它正是第一章那个"最小的连接"，伸到了最大尺度上：

> - 第一章：函数 A 调用函数 B（程序**内部**喊一声）。
> - 这一章：应用 调用 操作系统（程序向**整个系统**喊一声）。
>
> **同一种动作——"调用"，从两个函数之间，一路放大到了"应用与系统"之间。**
> 这正是序章许诺过的："最小的连接和最大的连接，其实是同一回事，只是尺度不同。"
> 走到这里，这句话终于兑现了。

但系统调用又和普通函数调用有一个**本质的不同**，这个不同至关重要：

当 CoinJar 调用自己内部的 `算服务费()` 时，控制权只是在它**自己的地盘**里转一圈。
但当它发起 `保存到文件()` 这个**系统调用**时，发生了一件大事——**控制权越过了应用和系统的边界，交到了操作系统手里。**

我们慢镜头看这次"越界":

```
CoinJar 想存账，于是发起系统调用：保存到文件("账目.txt", 数据)
        │
        ▼
控制权【离开】CoinJar 的地盘，【进入】操作系统的地盘     ← 关键的越界！
        │
        ▼
操作系统接管：它去驱动硬盘，让磁头转动，把字节真正写到盘片上
（这些又脏又危险的活，全由系统在它自己的地盘里干，CoinJar 看不见也碰不着）
        │
        ▼
干完了，操作系统把控制权【交还】给 CoinJar，并告诉它"存好了"
        │
        ▼
CoinJar 接着往下跑
```

请你品味这次"越界与归还"。它和第一章的调用栈（控制权的出借与归还）骨架完全一样，但跨越的是一道**更森严的边界**——应用和系统之间那道墙。为什么要有这道墙、为什么要这么严？因为这道墙保护着整台计算机的安全：

> 如果允许 CoinJar 直接去碰硬盘，那么一个写错了的、或者心怀恶意的程序，
> 就可能把整块硬盘格式化、把别的程序的数据冲掉、让整台电脑崩溃。
>
> 所以操作系统立下铁律：**应用一律不许直接碰硬件，想干"硬"事，必须通过系统调用来请求。**
> 系统在边界上当关卡，**逐一审核**这些请求（你有没有权限？这个操作合不合法？）。
> 那些又脏又危险的活，**只在系统自己的地盘里、由系统亲自来干。**

系统调用，就是这道墙上**唯一的、受到严格看守的门**。应用与系统的全部连接，都得从这扇门走。

## 6.5　进程：你的应用，是系统眼里的一个"住户"

要理解系统怎么管理 CoinJar，得先知道：在操作系统眼里，**一个正在运行的程序，叫一个"进程"**（process）。

注意"正在运行"这四个字。这里有个容易混淆、但很重要的区分：

- 硬盘上那一堆 CoinJar 的文件（第三、四章那些 `.py`），是**静止的、躺着的程序**——像一本**没人读的菜谱**。
- 当你**双击启动**它，操作系统就把它**请进内存、给它分配资源、让它跑起来**——这个"活起来的 CoinJar"，就是一个**进程**——像一个**正照着菜谱炒菜的厨师**。

> **程序是躺在硬盘上的"剧本"，进程是正在舞台上演出的那一场"演出"。**
> 同一个剧本可以演很多场——你可以同时开两个 CoinJar 窗口，那就是**两个进程**，
> 它们用的是同一份硬盘文件（同一个剧本），却是各演各的、互不相干的两场演出。

进程，就是操作系统这个"大楼物业"眼里的一个**住户单元**。物业以"进程"为单位来管理一切：

- **分房间**：给每个进程划一块**专属的内存**。这是操作系统极重要的一项保护——

> 每个进程的内存是**互相隔离**的，像公寓里**各家各户上了锁的房间**。
> CoinJar 这个进程，**看不到、也碰不到**浏览器进程的内存。
> 这样一来，一个程序崩了，**不会拖垮别的程序**——你的浏览器崩溃，不会让 CoinJar 跟着死。
> 这种"互相隔离、互不串门"的设计，是整台电脑能稳定运行的基石。

- **排时间**：CPU 在同一个瞬间其实只能干一件事，但操作系统让它在几十个进程之间**飞快地轮流切换**——给浏览器跑几毫秒，给 CoinJar 跑几毫秒，给音乐跑几毫秒……切换快到你完全察觉不到，于是看起来它们像在"**同时**"运行。这位大管家,把唯一的 CPU,公平地**分时**借给了所有住户。

- **管生死**：进程的"出生"（启动）、"死亡"（退出）、被强制"赶走"（你在任务管理器里"结束进程"），全部由操作系统说了算。

所以，当你启动和关闭 CoinJar 时，背后是操作系统在**接纳一个新住户、和送走一个旧住户**。CoinJar 的"生命",从头到尾,都攥在系统手里。

## 6.6　文件系统：应用怎么真正把账本存到硬盘上

现在我们回到最初那个痛点——CoinJar 一关账目就没了——把它彻底解决，顺便看清第三、四章那个"文件"，在硬件层面到底是怎么回事。

还记得第三、四章吗？我们聊了一堆"文件""目录""路径"。但那时我们其实**默认了它们的存在**，没问过一句：硬盘只是一大块能记录 0 和 1 的盘片，它上面凭什么会有"文件"和"文件夹"这种东西？谁把那一片混沌的磁记录，组织成了一个个有名字、能打开、还能放进文件夹里的"文件"？

答案是操作系统的一个核心部件——**文件系统**（file system）：

> 硬盘本身，只是一大片能存 0/1 的"荒地"。
> **文件系统**是操作系统在这片荒地上建立的一套**组织秩序**——
> 它把杂乱的磁记录，包装成"文件"和"目录"这些我们能理解的概念，
> 还维护着那棵第四章讲过的"目录树"，记着每个文件叫什么、在哪、占哪几块地。

所以第三、四章我们用得那么顺手的"文件"和"路径"，**全是操作系统的文件系统在背后撑着的**。我们当时享受的便利，此刻终于看清了它的来源。

于是 CoinJar"存账"这件事，完整的连接链是这样的：

```
你点了 CoinJar 的“保存”
        │
        ▼
CoinJar 发起系统调用：保存到文件("账目.txt", 账目数据)      ← 6.4 节
        │
        ▼
控制权越界，进入操作系统
        │
        ▼
操作系统的【文件系统】出马：
   · 在目录树里登记一个叫 "账目.txt" 的文件
   · 找一块空闲的硬盘区域
   · 驱动硬盘，把账目数据真正写成磁记录，落到盘片上
        │
        ▼
写完，控制权交还 CoinJar："存好了"
        │
        ▼
此后哪怕你关机、断电，数据也安安稳稳躺在硬盘上
```

下次你重新打开 CoinJar，它再发起一个"**读文件**"的系统调用，操作系统的文件系统就顺着目录树找到 `账目.txt`，把磁记录读回来，交给 CoinJar——于是**昨天的账，回来了。**

至此，上一章和本章开头那个"一关就没"的痛点，**根除了**。而根除它所依赖的，正是 CoinJar 与操作系统之间、通过系统调用建立的这层连接。

## 6.7　资源与权限：系统为什么不是有求必应

到这里你可能觉得：系统调用真好用，应用想要什么，喊一声系统就给。

但事情没这么简单。回到公寓比喻：你是住户，但你**不能为所欲为**——

- 你不能跑去拧别人家的水龙头；
- 你不能擅自闯进物业的配电房；
- 欠了水电费，可能会被停水停电；
- 半夜把音响开到最大，物业会来管你。

操作系统这位大管家，对应用也是一样——它**不是有求必应**的。它手握两把"约束的尺子":

**第一把尺子：权限（permission）。**

不是你想干什么，系统就让你干什么。系统会**审核**每一个请求：你有没有资格干这件事？

> - CoinJar 想读写**它自己目录下**的 `账目.txt`？——可以，这是你的地盘。
> - CoinJar 想去读**别的程序的**私密文件、或者系统的核心文件？——**驳回！** 你没这个权限。
> - 手机上一个 App 想读你的通讯录、开你的摄像头？——系统会**弹窗问你**："允许吗？"由**你**来授权。

权限，是系统在那道墙的门口设的**关卡**。它确保一个住户**不会越界去动别人的、或公家的东西**。这正是 6.4 节那道"墙"存在的意义在这里的具体兑现——墙不光挡着硬件，也挡着应用之间互相伸手。

**第二把尺子：资源是有限的。**

CPU、内存、硬盘空间,都是**有限**的,而住户有几十个。系统得**公平而有节制地分配**：

> - 内存就那么多，一个进程不能无限索取——要得太狠，系统会拒绝，甚至把它"请出去"（强制结束）。
> - CPU 时间是分片轮流的，没有哪个进程能独占。
> - 硬盘满了，"保存"这个系统调用就会**失败**——系统会老实告诉你的应用："没地方了。"

所以，一次系统调用，**完全可能被拒绝或失败**：没权限、内存不够、硬盘满了、文件不存在……

这件事对写程序的人有个深刻的提醒：

> **凡是跨出自己地盘、向系统提的要求，都可能被拒绝。**
> 所以一个健壮的应用，发起系统调用后，**必须老老实实检查结果**——
> 存成功了吗？还是硬盘满了？读到文件了吗？还是没权限？
> 不能想当然地以为"我要了，就一定给"。
>
> 这和应用内部的函数调用很不一样：
> 内部调用是"自己人",一般跑就跑通了;
> 而**跨越系统边界的连接,天生就带着"可能失败"的风险**——因为门那边,有一位会说"不"的管家。

记住这条，是从"会调用系统"到"能写出靠谱应用"的分水岭。**连接越往大尺度走，就越不可靠、越需要小心应对**——这条规律，到终章讲网络时,会变得更加突出。

## 6.8　回到 CoinJar：让它真正能存盘、能开窗、能退出

把这一章学的全部接到 CoinJar 身上，它终于要成为一个**完整、能落地**的单机应用了。我们让它做三件以前做不到的"硬"事，每一件都靠系统调用：

**① 能开窗**（启动时，请系统画出窗口）：

```
# 主程序.py
函数 启动():
    窗口 = 系统.创建窗口("我的账本", 宽=400, 高=600)   # ← 系统调用：请系统在屏幕上画窗口
    账目 = 从硬盘读账目()                              # （见下，启动就把旧账读回来）
    刷新账目列表()
    系统.进入消息循环(窗口)                            # ← 请系统：盯着这个窗口的鼠标键盘事件
```

**② 能存盘 / 读盘**（账目变化时存，启动时读——根治"一关就没"）：

```
函数 存账目到硬盘():
    结果 = 系统.保存到文件("账目.txt", 账目列表)        # ← 系统调用：请系统写硬盘
    如果 结果 == 失败:                                  # ← 6.7 节：系统调用可能失败，必须检查！
        显示("保存失败：可能硬盘已满或没有权限")
    否则:
        显示("已保存")

函数 从硬盘读账目():
    如果 系统.文件存在("账目.txt"):                     # ← 先问系统：这文件在吗？
        返回 系统.读取文件("账目.txt")                  # ← 系统调用：请系统读硬盘
    否则:
        返回 []                                         # 第一次运行，还没有账本，给个空的

# 把“存盘”挂到第五章的回调上：账目一变，就存一次
账目模块.当账目变化时 = 函数():
    刷新账目列表()        # 第五章：刷新界面

```

## 6.9　本章小结与断点预告

**这一章，我们建立了最大尺度的连接——应用与系统：**

- 应用程序像个"没有手脚的大脑"——它**不能直接碰硬件**，干不了存盘、开窗这些"硬"事。
- **操作系统**是所有程序共居的"大楼"和"地基"：它**驯服硬件**、**协调资源**。
- 整台计算机是**分层**的：应用层 → 系统层 → 硬件层——这是第五章"分层"思想的终极版本。
- **系统调用**是应用向系统"提要求"的标准方式——它就是第一章的"调用"放大到了最大尺度，但要**越过一道森严的边界**。
- **进程**是"正在运行的程序"，是系统管理的住户单元；进程内存**互相隔离**，一个崩了不连累别人。
- **文件系统**是操作系统在硬盘荒地上建立的秩序——第三、四章的"文件/路径"全靠它撑着。
- **权限与有限的资源**，是系统的两把尺子：系统**不是有求必应**，**跨边界的连接天生可能失败**，必须检查结果。
- CoinJar 终于成为一个真正落地的完整单机应用。

**到这里，一个完整的单机应用，圆满了。但是——**

请你回头看本章那张分层图，再想一个问题。CoinJar 现在能和它**脚下**的操作系统对话了。可它能和**另一台电脑上**的另一个程序对话吗？

- 你的账，能不能**同步到手机**上，让你在地铁里也能记一笔？
- 你和家人，能不能**共记一个账本**，你添一笔，对方那边立刻看到？

CoinJar 现在做不到。因为它的所有连接，无论多大尺度，都还**圈在你这一台机器的内部**。它和"**另一台机器**"之间，隔着一道它从未跨越过的鸿沟——网络。

而有意思的是,跨越这道鸿沟所用的思想,你其实**早就学会了**……

> **下一站，终章：走向外部世界。**
> 我们将回望这一路接起的所有连接，并看到：当 CoinJar 想和另一台电脑说话时，它用的，仍然是我们从第一章就在反复重演的那同一种思想——只是尺度，又放大了一圈。
