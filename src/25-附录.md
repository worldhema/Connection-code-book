 第十六部 模型↔工具  AI 能反过来调用记账/查账函数（工具调用，一个对话框取代所有按钮）

# 附录 B　术语小词典

> 按"它解决了什么连接问题"来解释。每个词，只讲它在"连接"这件事里扮演的角色。

### 卷一　单机篇

**函数（Function）**
一个有名字、有入口（参数）、有出口（返回值）的"任务"。它解决的连接问题：把一段活儿围起来，让别的代码能"喊"它。

**调用（Call）**
一个函数"喊"另一个函数帮忙。控制权的一次"出借与归还"。全书最小、也最核心的连接动作。

**参数 / 返回值**
调用这条通道上来回运送的"货物"。参数是上游给的原料，返回值是下游收的成品。它们让函数能像水管一样串起来。

**调用栈（Call Stack）**
记录"谁喊了谁"的一摞盘子，保证控制权去得了、也回得来。解决的问题：让连接是双向的。

**模块（Module）**
一组相关函数的"打包"，一个带标签的抽屉。解决的问题：函数太多时，怎么归类、怎么收纳。

**导入 / 导出（Import / Export）**
模块之间的"借用专线"：一个抽屉开放工具，另一个来借。模块间的连线。

**接口与实现（Interface / Implementation）**
接口是"我能干什么"的承诺，实现是"我怎么干"的做法。连接接在承诺上，不接在做法上——于是实现可换，接口不动。全书最重要的概念之一。

**依赖（Dependency）**
"谁离不开谁"。模块连接的方向性。好的依赖应单向流动，忌循环。

**命名空间（Namespace）**
每个模块的"专属名字地盘"。让成千上万的名字在各自地盘里和平共处，不重名打架。

**文件（File）**
代码的"身体"——一个名字 + 一段内容。让概念能被保存、打开、分发。

**引用（Reference）**
一个文件要用另一个文件的代码，先报出对方住址。文件间的连线。

**路径（Path）**
文件的"地址"。分绝对（从根数起）与相对（从自己数起）。寻址思想的起点。

**目录（Directory）**
能装文件、也能装目录的容器。让磁盘长成一棵树。既是容器，也是边界。

**事件（Event）**
用户的一个动作（点击、输入）被捕捉成的信号。把"界面上的操作"翻译成"代码里的调用"。

**回调（Callback）**
"我不盯着你，你办完了主动喊我"。被通知方留下联系方式，通知方照着喊却不必认识对方。贯穿全书的连接姿态。

**分层（Layering）**
界面与逻辑各管各的，只靠细线相连。上层通过中间层提要求，不直接碰底层。

**操作系统（OS）**
一台机器内所有程序共同的"地基"和"大管家"：驯服硬件、协调资源。

**系统调用（System Call）**
应用向操作系统"提要求"的标准方式。调用思想跨越"应用/系统"边界的放大。

**进程（Process）**
一个"正在运行的程序"。操作系统眼里的住户单元，内存互相隔离。

**文件系统（File System）**
操作系统在硬盘"荒地"上建立的秩序，把磁记录组织成文件和目录。

**权限（Permission）**
系统在边界上设的关卡："你有资格干这件事吗？"安全主线的起点。

### 卷二　网络篇

**网络（Network）**
让消息在不同机器间传递的"公共管道"。物理管道 + 一整套协议。

**IP 地址**
每台机器在全网的"门牌号"。路径（寻址）思想从"一块硬盘"放大到"全世界的机器"。

**数据包（Packet）**
把大消息拆成的、带编号的"小包裹"，各自寻址、乱序到达、按号重组。

**路由（Routing）**
数据包"一跳接一跳"被路由器接力转运。调用栈"接力传递"思想的放大。

**协议（Protocol）**
机器间事先约定好的"共同语言"（TCP/IP/HTTP…）。接口/约定思想的放大：任何独立双方连接，必先有共同约定。

**客户端 / 服务器（Client / Server）**
一个发起请求、一个提供服务。网络程序对话的基本角色。

**请求 / 响应（Request / Response）**
跨机器的"一问一答"。函数调用思想跨越机器边界的放大。

**端口（Port）**
IP 找到机器后，再找到机器上的"那个程序"。寻址的进一步收窄。

**域名（Domain Name）/ DNS**
IP 地址的"人类友好别名"。寻址的符号化简写。

**API（应用程序接口）**
服务器对外公开的"我能干什么、你怎么找我"的承诺。模块接口跨机器的放大。

**数据库（Database）**
服务器上专门管"存、取、查、改"的大管家。文件系统在云端的放大版，能处理多人并发、按条件查询、保证不丢。

**前端 / 后端（Front-end / Back-end）**
被网络鸿沟切开的"前厅与后厨"。前端管界面交互，后端管逻辑数据。第五部分层的放大。

**身份认证（Authentication）**
"你是谁？"——登录、令牌解决的问题。

**令牌（Token）/ 会话（Session）**
登录后服务器发的"电子工作证"。让"健忘的网络"记住"你是谁"，不必反复输密码。

**哈希（Hash）**
把密码单向"绞碎"再存。让服务器"能验证、不知道、偷不走"你的真密码。安全主线的高光。

**授权 / 权限（Authorization）**
"你能干什么？"——按角色决定能看 vs 能改。第六部系统权限的放大。

**第三方服务（Third-party Service）**
把"专业又危险的事"（如支付）外包给专门的公司。接口/隔离思想的最高升华。

### 卷三　智能篇

**大语言模型（LLM）**
一个"会理解、会生成语言"的大脑。能容忍模糊人话，因为它理解的是"意思"而非"字面"。

**提示词（Prompt）**
你对模型说的那句话。它就是这次"调用"的"参数"。调用思想的第五次放大。

**生成 vs 查找**
模型靠"生成"（像作家现场创作），不像数据库靠"查找"。代价：它会"编"（幻觉）、有不确定性。

**模型 API**
向云端 AI 大脑"提要求"的网络接口。系统调用/网络请求的放大。

**上下文（Context）**
每次请求附上的"历史对话"，让"健忘的模型"记住刚才聊了什么。会话思想的放大。

**提示词工程（Prompt Engineering）**
"怎么把话说清楚，让模型答得准"的学问。用自然语言"编程"。

**工具调用（Function Calling / Tool Use）**
让模型反过来"决定调用你的哪个函数、传什么参数"。"调用"思想最戏剧性的角色反转——决策权从人交给了 AI。

**工具描述（Tool Definition）**
写给"AI 看"的接口说明书。接口的读者第一次从人变成了 AI；接口与提示词在此合流。

**RAG（检索增强生成）**
先"检索"出相关私有数据、"增强"进提示词、再让模型"生成"回答。让 AI "不懂先查、基于资料再答"，避免幻觉。

**语义检索（Semantic Search）**
按"意思"找，而非按"字面"找（"相机"能找到"佳能"）。寻址思想最深刻的放大——从"按地址找"到"按含义找"。

**向量（Vector）**
把文字的"含义"变成"语义地图上的坐标"。意思近，坐标近。把虚无的含义变成可计算的数字。

**智能体（Agent）**
会"思考→行动→观察→再思考"自主循环的 AI。从"被动应答的工具"，进化为"主动干活的助理"。

**编排（Orchestration）**
主管 Agent "拆解→分派→汇总"的统筹工作。第一部"总指挥函数"的最终放大。

**多智能体（Multi-Agent）**
多个各有专长的 AI 在主管统筹下分工协作。模块化分工思想在 AI 之间的重演。

**人在回路（Human-in-the-loop）**
无论 AI 网络多自主，人始终是最终节点：目标由人设、关键决策由人拍板、过程人可中断。安全主线的最终章。

# 附录 C　给想动手的读者：如何把书里的 CoinJar 真正跑起来

> 本书所有代码都是"可读优先"的示意伪代码。如果你想把 CoinJar 真正跑起来，这里给一条循序渐进的路线。**不必一次做完，每完成一卷，你的 CoinJar 就真实地长大一圈。**

### 准备工作

- 装一个你喜欢的编程语言环境。推荐 **Python**（语法接近本书伪代码，生态全）或 **JavaScript/Node.js**（天然适合做网页）。
- 装一个代码编辑器（如 VS Code）。
- 准备好"边查边学"的心态——遇到不懂的具体语法，搜索它、问 AI 助手，本书帮你建立的"整体感"会让你知道每段代码"为什么这么写"。

### 卷一：做一个能跑的单机记账本

1. **第一部**：写出 `解析输入`、`检查账目`、`记录账目`、`报告结果` 几个函数，和一个 `记一笔账` 总指挥。先在命令行里跑通"输入一句话→记一笔→打印结果"。
2. **第二~四部**：把这些函数拆进不同文件、不同目录，体会"引用"和"路径"。
3. **第五部**：用语言自带的 GUI 库（Python 的 tkinter、JS 的 Electron），给它装个窗口。
4. **第六部**：用文件读写（把账目存成一个本地文件），实现"关掉再打开，账还在"。

✅ **里程碑**：一个能记账、能存盘、有窗口的桌面小程序。

### 卷二：把它搬上云端

1. **第七~八部**：用一个 Web 框架（Python 的 **Flask/FastAPI**、JS 的 **Express**）写一个服务器，提供 `GET /账目`、`POST /账目` 接口。把记账本拆成"客户端 + 服务器"。
2. **第九部**：接一个数据库（入门用 **SQLite**，零配置；进阶用 PostgreSQL），把账目存进去。
3. **第十~十一部**：写一个 HTML 网页 + JS，让它向你的服务器发请求。能用浏览器打开记账了。
4. **第十二部**：加注册/登录（密码记得 **哈希**！用现成的库如 bcrypt），加令牌（用 JWT）。
5. **第十三部**：接一个支付平台的"沙箱/测试环境"（Stripe 的测试模式最适合学习），跑通一次模拟付款。

✅ **里程碑**：一个多人能用、需要登录、数据存在云端的真正 Web 应用。

### 卷三：给它装上 AI

1. **第十四~十五部**：注册一个模型 API（OpenAI、Anthropic 等都有），在后端调用它，把用户的"午饭花了18"变成结构化账目。
2. **第十六部**：用模型 API 的 **工具调用（function calling）** 功能，把你的 `记账`、`查账` 函数交给模型调用。
3. **第十七部**：接一个向量数据库（如 **Chroma**、pgvector），实现"按意思搜账目"。
4. **第十八部**：用一个 Agent 框架（如 **LangChain**、或直接用模型 API 的循环），让它自主完成多步任务。
5. **第十九部**：尝试拆成多个专长 Agent，让一个主管协调它们。

✅ **里程碑**：一个听得懂人话、会自主干活的 AI 记账管家。

> **温馨提醒**：动手时，请始终牢记书里的安全主线——
> 密码要哈希、不要相信前端、API 密钥藏在后端、给 AI 的工具要设边界、危险操作要人工确认。
> 把这些"缰绳"从第一天就装上，是好习惯。
